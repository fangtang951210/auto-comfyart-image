# 素材01:冷启动与通道(全部 2026-10-28 实测)

环境:Mac + Safari;ComfyUI 在 170hx(10.0.0.191:8188);ComfyArt 项目 id 61fadeda。

## 冷启动三步(从画布关闭状态到 MCP 可用)

```bash
# ① 起 Safari 控制器(常驻单会话;脚本见本仓库 工具/safari-controller.py)
nohup python3 ~/Documents/tmp/safari-controller.py > ~/Documents/tmp/safari-controller.log 2>&1 &

# ② 一条命令直达画布(带 ?project= 参数直连,不要走列表页点击!)
echo '{"id":1,"name":"navigate_to_url","args":{"url":"http://10.0.0.191:8188/comfyart/?project=61fadeda"}}' > /tmp/safari-ctl.fifo
# 等 15-20 秒页面加载;验证:evaluate_javascript 查 document.querySelector("canvas") 存在

# ③ 验证 MCP 通道
# 在 Claude Code 里调 comfyart 的 server_info / list_models,返回即通
```

关键事实:
- **直连 URL 必须带 `?project=<id>`**,这是唯一可靠的直达方式;hash 路由(#/p/xxx)无效
- ComfyArt 的画布工具由**开着的浏览器标签页执行**,页面关了工具全部超时("the ComfyArt page did not finish")
- navigate 之后 evaluate 若报 "Could not find browsing context"=页面 reload 过,控制器上下文失效,重启控制器再 navigate
- **浏览器只做激活这一件事**;提示词/参考图/生成/等待全走 MCP

## 模型选择(MCP)

- `list_models`:列出可用模型。图片模型含内置(qwen-image-2.1 / z-image-turbo / ideogram4)+ 自定义流(`custom:generate`,label=当前 assign 的文件名)
- 自定义流的 id 恒为 **`custom:generate`**(源码常量),不是文件名
- generate_image 传 `model:"custom:generate"` 即用自定义流;不传 model = 列表第一个
- **切换自定义流 = `custom_workflow assign`**(换 generate 槽的文件),assign 后页面需重新加载才会反映到 list_models(reload 或重开画布)

## 大坑:模型偏好过滤

`ComfyUI用户目录/comfyart/models.json` 若为 `{"auto":false,"enabled":[...]}`:
- enabled 白名单**不含 custom:generate**(默认只列内置)→ 自定义流从 MCP 列表里消失,generate_image 报 unknown model
- 症状:UI 下拉能选自定义流、MCP 却看不到(两条列表路径不同)
- 修复:`"auto": true`,然后 reload 画布
- 排查顺序:先查这个文件,再怀疑其他
